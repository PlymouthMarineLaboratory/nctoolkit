Opening FVCOM output

To work with FVCOM model output use open_fvcom. Raw FVCOM output is not compatible with NCtoolkit's computational backend CDO. The open_fvcom function will convert the raw data to a format that is. By default, all the variables on the nodes of the mesh (and on the sigma layers, or with no vertical axis) are opened.

python
import nctoolkit as nc

ds = nc.open_fvcom("fvcom_0001.nc")

In cases where you only want to analyse a subset of data it is better to specify this when you open the data. You can do this as follows:

python
ds = nc.open_fvcom("fvcom_0001.nc", variables=["temp", "salinity"])

You can pass a list of files or a wildcard. Each FVCOM file becomes one file in the dataset:

python
ds = nc.open_fvcom("output/*.nc", variables="temp")
How does open_fvcom work?

It opens the raw netCDF data and then converts it to a new netCDF file that has coordinates and vertical thickness for each cell, based on the sigma layer information.

Internally, the dataset tracks what is what, and methods such as vertical_mean automatically identify the vertical thickness of cells for their calculations.

The variables you request must all live on the same part of the mesh. Node variables (e.g. temp, salinity, zeta) can be opened together, and so can element variables (e.g. u, v, ua). To work with both, open them separately. Element variables such as u and v are never opened by default, so request them explicitly:

python
ds = nc.open_fvcom("fvcom_0001.nc", variables=["u", "v"])

Opening puts the data on a grid that CDO understands:

  • Each node or element is a grid cell with its true area. Node cells are FVCOM's own control volumes (areas stored as art1), and element cells are their triangles.
  • The sigma layers become vertical levels, numbered from 1 at the surface.
  • The thickness of each layer, (siglev[k] - siglev[k + 1]) * (h + zeta), is added as a variable called layer_thickness. It changes with the free surface at each time step.

Two dataset attributes record this:

python
ds.fvcom            # True
ds.fvcom_thickness  # "layer_thickness"

Vertical methods

The vertical methods use the layer thickness automatically, so you do not need to supply thickness or fixed:

python
ds.vertical_mean()                       # thickness-weighted depth average
ds.vertical_integration()                # depth integral
ds.vertical_mean(depth_range=[0, 20])    # the top 20 m
ds.vertical_interp([5, 10, 50])          # values at fixed depths below the surface
ds.top()                                 # the surface layer
ds.bottom()                              # the bottom layer

When interpolating to fixed depths, depths above the centre of the top layer take the top layer's value. Depths between the centre of the bottom layer and the seabed take the bottom layer's value. Depths below the seabed are missing.

The layer thickness must stay in the dataset. If you select variables, keep it:

python
ds.subset(variables=["temp", "layer_thickness"])

Arithmetic with a constant, e.g. ds.add(1), also changes the layer thickness.

Spatial averages and regridding

Every cell has its true area, so spatial statistics are area weighted:

python
ds.spatial_mean()
ds.crop(lon=[-6, -4], lat=[50, 51])
ds.cell_area()

Regridding computes weights on the mesh itself. The bil method (the default) interpolates linearly within the mesh's triangles. nn takes the nearest node, or the element a point falls in. Places outside the mesh are missing, as are places next to missing values.

python
ds.to_latlon(lon=[-10, -2], lat=[48, 57], res=0.05)
ds.regrid(grid_ds)
ds.to_transect(start=[-6, 50], end=[-4, 51])
ds.match_points(df)

con, con2, laf and dis are also available. Once regridded, the data is no longer on the FVCOM mesh, so ds.fvcom is False. The vertical methods still use the layer thickness.

Methods that do not work with FVCOM data

These methods need a regular grid, or make no sense on the mesh. They raise an error saying they do not work with FVCOM data. If you need them, regrid the data first, e.g. with to_latlon.

  • zonal_mean, zonal_sum, zonal_min, zonal_max, zonal_range
  • meridonial_mean, meridonial_min, meridonial_max, meridonial_range
  • box_mean, box_sum, box_min, box_max, box_range
  • resample_grid, distribute
  • invert("latitudes")
  • strip_variables, which would remove the mesh's coordinates
  • set_gridtype, fix_amm7_grid, fix_nemo_ersem_grid
  • generate_level_bounds, and vertical_mean/vertical_integration/vertical_interp with fixed=True
  • crop with nco=True

All other methods work as they do for any other data.
